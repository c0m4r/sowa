Release 0.1 · x86_64 · experimental

A Linux system small enough to read.

Sowa builds an x86_64 cross toolchain, kernel, userspace, live ISO, installable disk images and a signed binary package repository from checksum-pinned upstream sources — without installing a single file into the host it was built on.

Download the live ISO All downloads

Built for servers and headless machines. No desktop, no systemd, no compatibility promises.

root@sowa:~
root@sowa:~# sowa-setup

root@sowa:~# sowa-pkg install nginx
... verified against the signed repository

What you actually get

Every component has a build stage, a package record and a file manifest. Nothing arrives by autodetection, and nothing is copied in from the host.

Its own init

sowa-init is a System V-style init and service framework written for this system: rc.d scripts, a service command, and an rc.sysinit that serves both the live medium and an installed disk.

Signed packages

sowa-pkg installs from a self-hosted repository whose metadata is signed. The release key that covers boot media is deliberately separate from the online repository key.

Declarative networking

nic configures interfaces and firewall from /etc/nic.conf over iproute2 and iptables. The default drops inbound traffic and permits only ICMP and SSH.

Key-only root

OpenSSH is enabled out of the box, root login is strictly key-based, and the root account ships with no password. Remote access stays closed until you install a key.

Self-hosting toolchain

binutils and GCC are built a second time to run on Sowa, so the installed image compiles C and C++ — headers, static libraries, make, m4, autoconf and pkg-config included.

A one-megabyte early boot

The live initramfs holds a single static program, liveinit, which finds the medium, loop-mounts the squashfs, overlays a tmpfs and switch_roots. There is no shell in it on purpose.

Try it in QEMU first

make run-iso
make disk-image run-disk-image

Exit a headless QEMU session with Ctrl-a x. The live image starts on a passwordless root console.

Or build the whole thing yourself

On a prepared x86_64 Linux host. Sources are pinned in config/sources.lock and verified by SHA-256 whether the primary URL or a mirror answers. The update check reports newer upstream releases; it never rewrites the pins. 

make check
make check-updates
make fetch
make all

The bootstrap chain is explicit

cross binutils
  -> bootstrap GCC (C only, no libc)
  -> Linux UAPI headers
  -> glibc headers and start files
  -> target libgcc
  -> complete glibc
  -> final GCC (C and C++)
  -> Bash, ncurses, OpenSSL, zlib, curl, Python
  -> e2fsprogs, dosfstools, GRUB
  -> native binutils -> native GCC
  -> kernel and sowa-init
  -> root filesystem
  -> squashfs + liveinit initramfs
  -> bootable ISO

A containerised build environment is available too: docker/sowa-env.sh run make all. Outputs land in artifacts/; JOBS, WORK_DIR, DOWNLOAD_DIR and ARTIFACT_DIR control parallelism and placement.

Packages

The base image is a terminal-oriented administration and development system: Bash, coreutils, Vim and nano, OpenSSL and curl, Git, Python and Perl, iproute2 and iptables, OpenSSH, WireGuard and OpenVPN, BIND tools, chrony, cron, syslog-ng, filesystem and boot tooling, and the native C/C++ toolchain. Each is packaged separately, and the rootfs build rejects any file without exactly one owner.

sowa-pkg update

Distribution is hybrid on purpose: some software ships as binaries built from source through sowa-pkg, while others — Ollama, Node.js, Go, Rust — use installers that pull straight from the upstream vendor. Services from optional packages stay disabled until you enable them.

Read this before you deploy it

Sowa is experimental and comes with no warranty. There is no fixed release cycle, no update model and no backward-compatibility promise; patches land on a best-effort basis. If you want a polished desktop or a supported server platform, this is not it.

If you miss small Unix-like systems, want to see what every part of a machine is doing, and are willing to be on your own — you are in the right place.
